## 一、项目介绍

### 1.1 研究背景

随着自动驾驶技术的快速发展，目标检测与跟踪作为感知系统的核心模块，直接影响车辆的决策与控制能力。传统的检测算法依赖手工设计特征，而深度学习方法通过大规模数据训练，能够自动学习目标特征，显著提升检测精度和鲁棒性。

CARLA（Car Learning to Act）是一个开源的自动驾驶模拟器，提供高度逼真的虚拟环境和多样化的传感器模拟，为自动驾驶算法的研究和测试提供了理想平台。

### 1.2 项目目标

本项目基于 CARLA 模拟器，复现并对比多种主流的 2D 目标检测与跟踪算法，主要包括：

- **检测算法**：Faster RCNN(Faster Region-based Convolutional Neural Network)、YOLOv4(You Only Look Once v4)、SSD(Single Shot MultiBox Detector)、Ground Truth（GT）规则引擎
- **跟踪算法**：SORT、DeepSORT、OC-SORT、StrongSORT

通过实验对比，分析不同算法的性能特点和适用场景，加深对目标检测与跟踪技术的理解。
## 二、方法对比
### 2.1 检测算法对比
本项目复现了四种检测方法，其核心特点对比如下：

|算法 |类型 |检测速度 |检测精度 |核心特点|
|----|----|----|----|----|
|Faster RCNN|两阶段检测|较慢（~1-3 FPS）|较高|先生成候选区域，再分类回归，精度优先|
|YOLOv4|单阶段检测|较快（~3-10 FPS）|中高|直接回归目标位置和类别，实时性好|
|SSD|单阶段检测|较快（~5-15 FPS）|中等|多尺度特征图检测，适合小目标|
|Ground Truth (GT)|规则引擎|极快（~20+ FPS）|100% |直接从 CARLA 获取真实数据，无需训练|

** 关键区别 **

- 深度学习方法 （Faster RCNN、YOLOv4、SSD）需要 GPU 加速才能达到实时性
- GT 方法 无需训练和 GPU，通过几何投影直接获取目标信息

### 2.2 跟踪算法对比
跟踪算法负责在连续帧中保持目标身份，本项目复现的四种跟踪算法特点如下：

|算法 |核心技术|优势 |适用场景 |
|----|----|----|----|
|SORT|卡尔曼滤波 + IOU 匹配|简单快速，易于实现|基础跟踪任务|
|DeepSORT|外观特征 + 卡尔曼滤波|ID 切换少，鲁棒性强|复杂场景下的长时跟踪|
|OC-SORT|遮挡感知 + 运动建模|处理遮挡能力强|密集目标场景|
|StrongSORT|ReID 特征 + 运动模型|长时跟踪稳定性好|视频序列跟踪|

核心原理 ：

- 数据关联 ：通过 IOU 或外观特征匹配前后帧目标
- 运动预测 ：使用卡尔曼滤波预测目标下一帧位置
- ID 管理 ：维护目标身份，处理新出现和消失的目标

## 三、实验结果与分析
### 3.1 实验环境
|配置项 |详情|
|----|----|

|硬件|CPU（无独立显卡）|

|主要依赖|tensorflow==2.3.0、torch==1.7.0+cpu、torchvision==0.8.1+cpu|

限制说明 ：由于实验环境无 GPU 加速，深度学习模型（YOLOv4、Faster RCNN）在 CPU 上运行速度较慢，主要用于功能验证。
### 3.2 性能对比
在 CARLA 模拟器中进行了多组实验，主要评估指标包括：

|检测+跟踪组合|平均 FPS|检测框数量|跟踪稳定性|
|----|----|----|----|
|Faster RCNN + SORT|~1-3|较少|一般|
|YOLOv4 + SORT|~1-3|中等|一般|
|GT + DeepSORT|~20+|较多|较好| 
|GT + OC-SORT |~20+|较多|较好|

** 关键发现 **

- GT 方法 无需 GPU，速度最快，适合验证跟踪算法逻辑。
- 深度学习方法 在 CPU 上速度受限，但检测效果更接近真实场景。
- 跟踪稳定性 与检测质量直接相关，检测越准确，跟踪越稳定。
- 通过查阅 CARLA 官方文档和 GitHub 社区讨论，发现 CARLA 的渲染器使用 64x64 的 tile 进行渲染。如果相机分辨率不是 64 的倍数，就会出现条纹状伪影。解决方案是将相机分辨率设置为 64 的倍数（如 448×448 = 7×64），然后通过中心裁剪得到所需的输入尺寸（如 416×416）。

## 四、个人贡献与改进
### 4.1 代码优化
在复现过程中，对原有代码进行了多项优化：

#### 4.1.1 线程通信优化

- 问题 ：2d-detection-frcnn原代码使用全局变量和轮询机制进行线程间通信，导致 CPU 占用率高、程序卡顿
- 解决 ：引入 queue.Queue 替代全局变量，使用 threading.Event 替代 stop_flag ，实现阻塞式等待
- 效果 ：显著降低了 CPU 占用率，避免了程序卡死现象
```python
# 优化前
while not stop_flag:
    continue  # 轮询等待，CPU 占用率高

# 优化后
origin_image = self.image_queue.get(timeout=1)  # 阻塞等待，CPU 占用率低
```
#### 4.1.2 车辆生命周期管理
- 问题 ：车辆被意外销毁后，程序崩溃并抛出 RuntimeError
- 解决 ：添加车辆存活检测 ( vehicle.is_alive )，在车辆销毁时自动重新生成
- 效果 ：程序稳定性提升，避免运行时崩溃

### 4.2 遇到的问题与解决
|问题 |原因 |解决方法|
|----|----|----|
|程序运行一段时间后卡死|线程通信机制不当|使用 Queue 替代全局变量轮询|
|图像显示条纹状伪影|CARLA 渲染分辨率不是 64 的倍数|将分辨率设为 64 的倍数（如 448×448），再中心裁剪到目标尺寸|
|车辆销毁导致崩溃|缺少存活检测|添加 is_alive 检查和自动重生|
|模型文件下载失败|网络/URL 问题|使用 GT 方法替代或手动下载|
|CPU 运行深度学习模型过慢|缺少 GPU 加速|使用 GT 方法验证跟踪逻辑|

### 4.3 未来改进方向
- GPU 加速 ：在具有独立显卡的环境下，使用 GPU 加速深度学习模型推理，提升检测速度
- 算法对比 ：在统一评估标准下，对多种跟踪算法进行量化对比（如 MOTA、MOTP 指标）
- 实时性能优化 ：研究模型剪枝、量化等方法，使深度学习模型在边缘设备上也能实时运行
